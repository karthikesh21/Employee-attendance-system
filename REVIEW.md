# REVIEW.md

Comprehensive code review of the starter implementation in `app/main.py`.

## Defects Identified and Fixed

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 33-37) | (a) Naive timestamp manipulation using `.replace(hour=h, minute=m)` without converting `punch_in` to IST (UTC+05:30) compares UTC timestamps against IST hour values. (b) Grace period logic `minutes > 10` checks floor minutes instead of elapsed seconds. At 09:40:01 (601s elapsed), `minutes` is 10, so `10 > 10` is False, returning 0 instead of 10. (c) Fails for overnight shifts where punch-in is past midnight. | Punch in at 09:40:01 for a 09:30 shift: returns 0 instead of 10 minutes (violating Rule R2). For UTC `04:10:00Z` (09:40 IST), computes against 09:30 UTC. | Convert `punch_in` to IST, establish shift start instant on the IST attendance date, calculate `diff_sec = (punch_in_ist - shift_start_ist).total_seconds()`, check `diff_sec > 600`, and return `int(diff_sec // 60)` when true, otherwise 0. |
| 2 | `compute_work_hours` (lines 40-41) | (a) Uses Python's built-in `round()`, which applies banker's rounding (round half to even) rather than standard half-up rounding required by Rule R4. (b) Does not truncate instants to whole seconds prior to calculation (Rule R1). | 9.125 hours yields `9.12` under banker's rounding instead of `9.13` under half-up rounding. Sub-second punch times skew exact work hours. | Truncate timestamps to whole seconds. Compute `Decimal(diff_sec) / Decimal(3600)` quantized to `0.01` using `ROUND_HALF_UP`. |
| 3 | `compute_overtime` (lines 44-47) | (a) Ignores the mandatory 30-minute threshold in Rule R3, returning overtime for any positive duration (`max(0, minutes)`). (b) For overnight shifts (`shift_end <= shift_start`), `shift_end` is on the next calendar day, but the function attaches it to `date_str` (the start date), resulting in an erroneous ~24-hour difference. (c) Can raise `TypeError` when subtracting naive and aware datetimes. | Punch out at 18:35 for an 18:30 shift (5 min overtime): returns 5 instead of 0. Overnight shift 22:00-06:00 punching out at 06:40 yields ~1480 min overtime instead of 40. | Check if overnight (`shift_end <= shift_start`) and advance shift end date by 1 day if so. Compute elapsed seconds between `punch_out` and `shift_end` in IST. If `diff_sec >= 1800` (30 min), return `int(diff_sec // 60)`, otherwise 0. |
| 4 | `GET /health` (lines 72-74) | Returns `{"status": "ok"}` unconditionally without checking MongoDB connectivity. OpenAPI contract specifies 200 only if MongoDB answers a ping, otherwise 503. | Terminate MongoDB or supply invalid `MONGO_URI`: endpoint still reports 200 OK. | Execute `client.admin.command('ping')` inside a try-except block. Return 200 if ping succeeds, otherwise raise `HTTPException(503, "Database unavailable")`. |
| 5 | `POST /employees` (lines 77-85) | (a) Check-then-insert race condition (`find_one` followed by `insert_one`) allows concurrent duplicate employee creations. (b) Missing unique index on `emp_code`. (c) Missing validation that `shift_start != shift_end`. (d) Stores naive `datetime.now()` and returns BSON datetime object instead of epoch milliseconds. (e) Missing Pydantic regex/length validations. | Send two concurrent `POST /employees` with identical `emp_code`: both succeed with 201 and insert duplicates. Create employee with `shift_start == shift_end`: succeeds with 201 instead of 422. | Create unique index on `emp_code` at startup and catch `DuplicateKeyError` to return HTTP 409. Add Pydantic model validators enforcing format, dates, and `shift_start != shift_end`. Store UTC BSON datetime and serialize `created_at` as integer epoch milliseconds. |
| 6 | `GET /employees` (lines 88-96) | (a) Offset calculation `skip = page * page_size` skips the entire first page; for `page=1, page_size=20`, `skip=20`, returning records 21-40. (b) `total = db.employees.count_documents({})` counts the entire collection ignoring the `department` filter. (c) Results are not sorted by `emp_code` ascending. (d) Response leaks BSON datetimes. | Calling `page=1, page_size=20` returns items 21-40. Calling with `department=Engineering` reports total count of all departments. Records are returned in arbitrary order. | Set `skip = (page - 1) * page_size`. Set `total = db.employees.count_documents(q)`. Add `.sort("emp_code", 1)`. Serialize `created_at` as epoch milliseconds. |
| 7 | `POST /attendance/punch-in` (lines 100-101) | Does not verify employee existence. If `emp_code` is unknown, `db.employees.find_one` returns `None`, and line 113 throws `TypeError: 'NoneType' object is not subscriptable`, crashing with HTTP 500 instead of HTTP 404. | Request with `{"emp_code": "EMP9999"}` returns unhandled HTTP 500 error. | Verify `emp = db.employees.find_one({"emp_code": body.emp_code})`. If `emp is None`, raise `HTTPException(404, "Employee not found")`. |
| 8 | `POST /attendance/punch-in` (lines 102-103) | (a) `datetime.fromtimestamp(body.punched_at / 1000)` produces naive datetime in host system timezone. (b) Date `ts.date().isoformat()` uses system date rather than IST calendar date. (c) Violates Rule R1 overnight shift rule: if punch-in occurs earlier than `shift_end` in IST, it belongs to the previous day's shift. (d) Missing epoch millisecond integer bounds validation (accepts strings, floats, seconds). (e) Does not truncate instants to whole seconds. | Employee on 22:00-06:00 shift punches in at 05:30 IST on 2026-07-07: assigned date `2026-07-07` instead of `2026-07-06`. Sub-second timestamps are not truncated. Submitting seconds-epoch `1783312500` succeeds instead of 422. | Validate epoch milliseconds (`100000000000 <= ms <= 4102444800000`). Truncate to whole seconds. Convert to IST, evaluate overnight shift boundary, store UTC BSON datetime in MongoDB, and serialize epoch milliseconds in API response. |
| 9 | `POST /attendance/punch-in` (lines 104-105) | Check-then-insert pattern on `(emp_code, date)` allows duplicate records under concurrency. No database unique constraint exists. | Send concurrent punch-in requests for same employee and date: both succeed and create duplicate documents. | Create compound unique index on `("emp_code", 1), ("date", 1)` at startup. Insert atomically and catch `DuplicateKeyError` to return HTTP 409. |
| 10 | `POST /attendance/punch-in` (lines 100, 118-121) | (a) Accepts any arbitrary status string instead of restricting to `PRESENT`, `WFH`, `ON_DUTY`. (b) Inserts `doc["id"] = str(res.inserted_id)` into response, violating the OpenAPI `AttendanceRecord` schema which disallows internal identifiers. (c) Returns raw BSON datetimes instead of epoch milliseconds. | Pass `status: "INVALID"`: accepted with 201 instead of 422. Response contains unexpected `id` property and ISO timestamp strings. | Validate `status` against `PresenceStatus` enum. Remove `_id` and do not expose `id`. Format `punch_in` and `punch_out` as integer epoch milliseconds (or null). |
| 11 | `GET /attendance` (lines 124-150) | (a) Fetches entire matching dataset into Python memory (`list(db.attendance_logs.find(q))`) and sorts/paginates in Python, which exhausts memory and causes high latency on 100k records. (b) Missing sorting in database by `date` desc, `emp_code` asc. (c) Does not validate `date_from <= date_to` (contract requires 422). (d) Injects `id` into documents and leaves BSON datetimes unformatted. | Calling `GET /attendance?date_from=2026-07-10&date_to=2026-07-01` returns 200 instead of 422. Memory usage spikes and performance degrades under load. Response schema fails validation. | Enforce `date_from <= date_to` validation returning 422. Push pagination and sorting down to MongoDB using `.sort([("date", -1), ("emp_code", 1)]).skip(skip).limit(page_size)`. Calculate `total` with `count_documents(q)`. Format records to match `AttendanceRecord`. |
| 12 | Database initialization (lines 20-27) | No indexes are created at startup. DATA_MODEL.md specifies that seeded MongoDB instances have only the default `_id` index. | Inspecting MongoDB `getIndexes()` shows only `_id_`. All queries and aggregations perform full collection scans (`COLLSCAN`). | Implemented `ensure_indexes()` called idempotently at application startup / lifespan, creating all necessary unique, compound, and sorting indexes. |
| 13 | Missing endpoints (lines 154-162) | The starter file left seven required endpoints unimplemented: `POST /attendance/punch-out`, `PATCH /attendance/{emp_code}/{date}`, and all four analytics endpoints (`/analytics/employees/{emp_code}/monthly`, `/analytics/departments/summary`, `/analytics/leaderboard/late`, `/analytics/departments/{department}/trend`), plus `/admin/explain/{endpoint}`. | Invoking any of these routes results in HTTP 404 / 405 Method Not Allowed. | Implemented all seven endpoints in `app/main.py` strictly conforming to `openapi.yaml`, using MongoDB aggregation pipelines, atomic operations, and explain execution plans. |
| 14 | Input timestamp validation (`PunchInIn`, lines 63-67) | The starter model defined `punched_at: Optional[int] = None` without strict type guards. Default Pydantic parsing coerces numeric strings (`"1783312500000"`) and floats to integers without validation, violating the contract ("floats, strings and out-of-range numbers are rejected with 422"). | Submitting `punched_at: "1783312500000"` or float timestamps was accepted instead of returning HTTP 422. | Added pre-coercion validators (`mode="before"`) for `punched_at`, `punch_in`, and `punch_out`, strictly enforcing `isinstance(v, int)` and rejecting booleans, floats, strings, and out-of-range numbers with 422. |

## Examined and Confirmed Correct

- **FastAPI default error formatting**: The starter uses FastAPI's default error body format `{"detail": ...}`, which matches the OpenAPI contract `#/components/responses/Error` and `#/components/responses/ValidationError`.
- **Environment variable precedence**: The starter loads `.env` with `load_dotenv()`, while ensuring that real OS environment variables take precedence over values in the file when `MONGO_URI` and `MONGO_DB` are accessed.
- **Collection naming**: The collection names `employees` and `attendance_logs` in the starter match the specification in `DATA_MODEL.md`.
